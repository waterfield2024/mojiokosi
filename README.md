# Whisper Local

YouTube・保存した動画・PCで再生中の音声を、日本語の字幕にするWindows向けPythonプログラムです。
ソースをクローンし、自分のPCのPython環境で起動します。独自の起動用EXEは配布しません。

## 必要なもの

- Windows 10 / 11、64ビット（x64）。macOS・Linux・Windows ARMは対象外です。
- 初回セットアップ用のインターネット接続と、目安として20 GB以上の空き容量。選ぶモデルにより追加容量が必要です。
- NVIDIA GPUは任意です。対応するドライバーがあればCUDA、GPUがない場合はCPUで利用できます。CPUでのリアルタイム認識は処理が追いつかない場合があります。
- Pythonは自動で準備します。Gitはクローンする場合だけ必要です。Gitがない場合はGitHubの「Code → Download ZIP」を展開して使えます。

Python本体もこのフォルダー内に準備します。`.python/runtime` または `.python/3.12.10` がなければ
[Python公式のWindows配布](https://www.python.org/ftp/python/index-windows.json)にある3.12.10を
`.python/3.12.10` に取得し、SHA-256で確認して展開します。ライブラリは `.venv` に作ります。
コピー先では、同梱したPythonを使って `.venv` の参照先を自動修復します。
管理者権限、PATHの手動設定、PowerShellの実行ポリシー変更は不要です。

## 最初の1回

**ダウンロードしたフォルダーの `start.cmd` をダブルクリックしてください。初回の準備からアプリの起動まで自動で進みます。**

Gitを使う場合：

```powershell
git clone https://github.com/waterfield2024/mojiokosi.git
cd mojiokosi
.\start.cmd
```

セットアップはPython、Pythonライブラリ、FFmpeg、Node.js、話者判別モデル、軽量Whisper baseを取得します。
NVIDIA GPUを検出した場合はPyTorchのCUDA 12.8版、それ以外はCPU版をインストールします。
NVIDIA GPUでは**Nemotronのノイズ除去モデルと必要なライブラリも自動で準備**します。
CUDAの動作確認に失敗した場合はCPU版へ切り替えて、通常の文字起こしを使えるようにします。
ノイズ除去のオン・オフはアプリで選びます。CPU版ではノイズ除去は使えません。
モデルとNode.jsは固定した配布元とSHA-256で照合します。ダウンロードには数分以上かかります。
進み具合は5段階で表示します。失敗した場合は画面を残し、詳細を `.cache/setup.log` に保存します。
同じ `start.cmd` をもう一度開くと、取得済みのファイルを再利用して準備をやり直します。

次回からはインストール済みのライブラリと必要ファイルを確認して起動します。
セットアップが完了していて依存関係に変更がなければ、起動時の再インストールや通信は行いません。
更新版に必要なライブラリが増えたときやファイルが不足しているときは、自動でセットアップを実行します。
設定、話者名、学習音声、誤変換辞書はそのまま引き継ぎます。

処理方式を指定する場合：

```powershell
.\setup.cmd --device cpu
# NVIDIA GPU用
.\setup.cmd --device cuda
```

高精度モデルも先に準備するなら `--model turbo` を追加します。
`small`、`granite`、`haas` も指定できます。セットアップ後に画面で選んでも、初回利用時に取得します。
セットアップが途中で失敗した場合は、表示された原因を解消して同じコマンドを再実行してください。
CPU版とCUDA版を切り替える場合も上記のセットアップを再実行します。
自動判定へ戻すには `setup.cmd --device auto`。準備だけを行う場合も `setup.cmd` を使います。
手動で選んだ処理方式と準備モデルは、次回の自動セットアップにも引き継ぎます。

## 起動

**毎回 `start.cmd` をダブルクリック**します。準備済みならすぐにアプリを開きます。
Pythonのコマンドを使う場合は `.\.venv\Scripts\python.exe run.py` でも起動できます。
仮想環境のActivateは不要です。

画面の主な使い方：

1. YouTubeのURLを貼る、または音声・動画ファイルを選びます。
2. 「話者判別・文字起こしを開始」を押します。
3. 結果の文章・話者・時刻を確認して、テキストや字幕付きMP4に保存します。

PCの再生音声には「PC音声をリアルタイム…」を使います。録音のみ・画面録画・ウィンドウ録画を選べます。
音声の区切り方は「話の切れ目で区切る」が標準です。話の途中は暫定字幕を差し替えて表示し、
声が途切れたら、まとまった音声を認識し直して確定します。表・履歴・保存・話者学習には確定結果だけを使います。
「字幕の更新間隔」は暫定字幕の更新頻度です（標準2秒）。停止時も最後まで確定します。
「話し続けたときの上限」は8・12・20・30秒から選べます（標準12秒）。長い文章が途中で分かれる場合は20秒や30秒に伸ばしてください。
無音が続けば上限より前でも確定します。上限で区切る場合は、次の区間に1秒の音声を重ねます。
上限は録音中も変更できます。短くした時点で既に上限を超えている音声は、そのまま確定して次の発言から短い上限を使います。
長い設定ほど確定までの時間と処理負荷は増えますが、途中の暫定字幕は更新し続けます。上限は自動保存され、次回起動・バックアップ復元でも引き継ぎます。
「区切るまでの無音」は0.3〜3.0秒から選べます（標準0.7秒）。息継ぎで分かれる場合は1.2秒や1.5秒に伸ばしてください。
録音中にも変更でき、未確定の発言から適用します。長くすると確定までの待ち時間も延びますが、暫定字幕は更新し続けます。
無音の長さは自動保存され、次回起動時やバックアップ復元時も引き継ぎます。
従来の区切り方は「秒数で区切る（従来）」から選べます。選択は自動保存されます。
Whisperでは「前の文章を参考に認識する」が標準でオンです。直近2つの発言（合計最大160文字）を
次の認識のヒントにし、約6秒以上発言が途切れた場合や停止・再開時は文脈をリセットします。
話題・専門用語のヒントと併用でき、AI校正がオフでも動作します。追加の音声を待つ処理はありません。
前の誤認識が続く場合は、開始前にこのチェックを外してください。設定は自動保存されます。
Granite・Haasはこのヒントに対応していないため、選択中はチェック欄を操作できません。
無音や雑音だけの区間を認識に渡さないよう、発話の有無を自動判定します。Whisper・Granite・Haas共通で、
Nemotronでノイズ除去した音声にも適用します。録音の音声や時刻は変えません。
軽量なSilero VADモデル（約2.3MB、CPUで処理）は自動セットアップで取得し、停止後も保持します。
短い返事を残すため、文字の「ん」を一律に削除する方式にはしていません。
小さい声や短い返事が消える場合は、リアルタイム画面の「無音判定の感度」を
「小さい声・短い返事を拾う」に変更してください。「雑音を抑える」「標準」（初期設定）と合わせた3段階です。
録音中にも変更でき、次の音声区間から反映します。設定は自動保存され、次回起動時やバックアップ復元時も引き継ぎます。
感度を上げると雑音も拾いやすくなるため、誤認識が増えたら「標準」に戻してください。
開始後の停止・再開は `Ctrl + Alt + F9`。録画を止めて再開すると、新しい録画として保存します。
話者名の記憶、学習音声の確認、字幕の縦書き、プレビュー編集、WhisperとGraniteの比較も利用できます。
詳しい画面操作は [使い方](docs/使い方.txt) を参照してください。

## 画面端の履歴と検索

リアルタイム開始後は、画面の右端に文字起こしをチャット形式で表示します。
話者名・時刻・文章が並び、メイン画面を最小化しても表示を続けます。
通常画面の「2. 確認・修正する」→ **履歴・検索** からも開けるので、保存済みの結果も検索できます。

- **表示**：直近100件が標準です。50・100・200件に変更できます。表示件数を減らしても元の文字起こしは削除しません。
- **検索**：入力した語を本文・話者名から探し、一致箇所を色付きにします。英字の大文字・小文字は区別せず、記号もそのまま検索します。
  対象は現在開いている結果の全文です。画面に出ていない古い発言も探せます。複数の録音を横断する検索ではありません。
- **古い発言／新しい発言**：表示件数を超える履歴や検索結果を前後にたどれます。
- **発言をクリック**：検索結果や履歴の文章・話者名・時刻をクリックすると、その発言の開始から終了までの音声を再生します。
  別の発言をクリックすると切り替わります。**音声を停止** または `Esc` で停止でき、検索変更・ページ切り替え・パネルを閉じたときも止まります。
  文字をドラッグして選択するだけでは再生しません。音声はWindowsの既定の再生先から出力します。
- **再生速度**：パネル下部で0.5・0.75・1・1.25・1.5倍を選べます。声の高さを保ったまま、発言の最後まで再生します。
  再生中に速度を変えると、その発言の最初から聞き直します。選んだ速度は次の発言にも使います。
- スクロールや文字選択をすると自動追従を止めます。新しい発言が届いても閲覧位置は動きません。
  **最新へ** で検索を解除し、最新の発言を追います。選択した文章は `Ctrl+C` でコピーできます。
- **配置**で左右の画面端を選べます。位置・大きさはドラッグでも調整でき、表示件数・表示のオン／オフとともに次回へ引き継ぎます。
- パネルの閉じるボタン、またはリアルタイム設定の「画面端に文字起こし履歴を表示」で非表示にできます。
  認識・録音はそのまま続きます。履歴は停止後も確認でき、別の結果を開くとその内容に切り替わります。

アプリにフォーカスがあるときは `Ctrl+F` でも検索欄を開けます。
字幕の修正・話者名の変更は履歴にも反映します。ライト／ダーク／Windows設定に追従し、
アプリ自身による画面録画からは履歴パネルを除外します。

音声確認には結果フォルダー内の保存音声（`.audio`）を使います。結果を移すときはフォルダー全体を移してください。
音声が残っていない場合はパネル下部に理由を表示します。リアルタイム録音中も保存済みの区間を再生できますが、
同じ出力先の音を録音していると再生音も取り込まれるため、重複を避けたい場合は録音を停止してから確認してください。

## Haas-ja-v1.0を使う

通常画面、またはリアルタイム画面の「認識モデル」で **Haas-ja-v1.0（CPU）** を選びます。
初回に約481 MBのモデルを取得し、次回から保存済みのモデルを使います。
事前に取得する場合は `setup.cmd --model haas` を実行してください。

- 日本語専用です。言語欄の選択や「話題・専門用語」のヒントは使いません。
- [公式モデル](https://huggingface.co/third-intelligence/Haas-ja-v1.0)はLinux＋NVIDIA GPU向けのため、
  このWindows版では[コミュニティの量子化ONNX変換版](https://huggingface.co/oboroge0/Haas-ja-v1.0-onnx-quantized)を使用します。
  Third Intelligenceによる公式Windows版ではありません。前処理・量子化が異なり、公式版と同じ認識結果・精度・速度は保証しません。
- Haasは「GPU優先」を選んでもCPUで動作します。WhisperとGraniteのGPU設定はそのままです。
- YouTube・保存ファイル・リアルタイムに対応し、話者名、誤変換辞書、文脈校正、字幕付きMP4にも既存の機能を使えます。
  リアルタイムでは短い音声区間ごとに認識します。停止後もモデルを保持し、再開時に再利用します。
- リアルタイムで選んだモデルは次回起動時にも復元します。読み込み途中で別のモデルを選んだ場合は準備を中断します。
- 長い音声は20秒以内に区切ります。時刻はモデルのトークン時刻を使い、対応が取れない区間だけ区間全体の時刻に戻します。
  字幕の時刻・文章はプレビューで確認・修正できます。
- 「2モデルで比較」は引き続きWhisperとGraniteの比較です。

追加のPythonライブラリ、WSL、APIキーは不要です。モデルは固定リビジョンとSHA-256で確認し、
外部のPythonコードをダウンロードして実行することはありません。

## リアルタイムのノイズ除去

「PC音声をリアルタイム…」で **Nemotronでノイズ除去（認識用のみ）** をオンにします。
NVIDIAの[NemotronLabs RE-USE](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-RE-USE)を使用し、
Whisper・Granite・Haasへ渡す音声だけを処理します。初期状態はオフで、選択は次回起動時にも復元します。

- **元の録音を保持**：録音WAV・保存FLAC・MP4の音声・履歴の音声再生は元の音声です。話者判別や話者の学習にも元の音声を使います。
- **録音中も切り替え可能**：メイン画面を開き、「PC音声をリアルタイム…」からチェックを切り替えると、次の音声区間から反映します。既に認識した文章は書き換えません。
- **先読みして再利用**：GPU版の自動セットアップで約39MBの重みを準備します。未取得の場合は初回オン時に取得します。読み込み後は停止・再開でも保持します。録音中に初めてオンにした場合は、準備が終わるまで元の音声で認識を続けます。
- **遅延・エラー時は継続**：処理が遅い場合やGPUメモリー不足などで失敗した場合、ノイズ除去を休止して元の音声で文字起こしを続けます。理由はチェック欄の下に表示します。再試行はオフ→オンです。
- **NVIDIA GPUが必要**：CUDA版PyTorchで動きます。処理方式をCPUに固定した場合はノイズ除去を休止します。Haasを選んでも、ノイズ除去自体はGPUで処理します。

このWindows実装は、公式の固定した重みとモデル構造を使い、Mambaの計算部分をPyTorch付属NVRTCで実行します。
WSL・Docker・別のCUDA Toolkitは不要です。NVIDIA公式のWindows版ではありません。
通常版RE-USEを短い区間ごとに処理し、`Real-time_RE-USE`という別モデルには切り替えません。
RTX 2070 SUPERで2秒の音声のノイズ除去を約0.39秒で確認しました（先読み後・このPCでの測定、文字認識時間は別）。
GPUや同時実行中のアプリで速度は変わります。

雑音による聞き間違いの軽減を狙う機能です。精度の向上は音声ごとに異なり、声が重なる場面では
ほかの話者の声を抑える場合があります。取りこぼしがあるときはオフにしてください。
設定画面が収まりきらない場合は右側のスクロールバーを使えます。開始・停止ボタンは下部に固定しています。

## 文脈AI校正を使う場合だけ

認識・字幕・話者判別はOllamaなしで使えます。文章を文脈で校正する機能には、追加で
[Ollama for Windows](https://ollama.com/download/windows) と校正モデルを用意します。

```powershell
ollama pull qwen2.5:7b
```

Ollamaを起動して、アプリの「文脈AI校正」を有効にしてください。
新規利用者の自動校正は初期状態でオフです。以前に保存した設定は引き継ぎます。
音声認識・話者判別・校正はPC内で処理し、APIキーは不要です。
YouTube取得とソフト・モデルの初回取得には外部通信を使います。

## 更新とデータの引き継ぎ

アプリを終了してから実行します。

```powershell
git pull --ff-only
.\start.cmd
```

設定、話者名、学習音声、誤変換辞書、文字起こし結果は
アプリ内の `UserData` に保存します。初回だけ旧保存先 `%LOCALAPPDATA%\WhisperYouTube\UserData`
からコピーします。その後はアプリ内のデータを優先し、コピー先PCの既存データを混ぜません。
更新時は `UserData`・`.python`・`.venv`・`models`・`.tools` を残してソースを更新してください。

**別PCへはアプリを終了し、`whisper-local` フォルダー全体をコピーして、コピー先の `start.cmd` を開きます。**
隠し項目を含めたフォルダー全体をコピーしてください。Pythonのパス、録音・学習音声のパスは起動時に更新します。
準備済みのライブラリ・モデルは再利用し、同じ版ならコピー後の再インストールは不要です。
コピー先もWindows 10/11 x64が必要です。GPUはコピー先で判定し、利用できなければCPUで認識します。
別PCのウィンドウや音声出力先は再選択してください。認識モデル・字幕・話者名・辞書の設定は引き継ぎます。
アプリ外に置いた元動画を使う場合は、その動画もコピーするか、MP4出力時に選び直してください。
「バックアップ・復元」によるデータだけの移行も引き続き使えます。
モデル・キャッシュ・設定・音声・録画・バックアップはGitに登録しません。

## 困ったとき

```powershell
.\.venv\Scripts\python.exe run.py --check
```

- **Pythonが見つからない**：`start.cmd` を開いてください。未準備なら自動取得し、コピー済みなら参照先を修復します。
- **GPUが使えない**：アプリの「処理方式」をCPUに切り替えます。CUDA版のセットアップには対応するNVIDIAドライバーが必要です。GeForce RTX 4070 TiはCUDA対応ですが、この公開版ではその実機の検証はしていません。
- **文脈校正に失敗する**：Ollamaの起動と `ollama pull qwen2.5:7b` の完了を確認します。
- **YouTubeを取得できない**：公開状態やサイト側の変更による場合があります。アクセス権のあるローカル動画でも試せます。
- **Windowsが部品をブロックする**：GitHubから取得したソースでも、依存するPython拡張やFFmpegなどはWindowsの検査対象です。GitHubに置けば自動的に許可されるわけではありません。このセットアップはSmart App Control、Defender、証明書ストア、実行ポリシー、ファイルのブロック状態を変更しません。拒否されたファイル名を確認し、管理されたPCでは管理者へ相談してください。

ログは `.cache/jobs` にあります。ログや画像を公開するときは、音声・字幕・個人のパスが含まれていないか確認してください。

## 検証と開発

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

単体テストは一時的な保存先を使用します。認識精度、話者判別、画面録画は利用環境によって変わります。
自動字幕は必ず内容を確認してください。
